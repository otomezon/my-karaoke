# 実装判断・引き継ぎ

## 対象範囲

- ユーザー提供の「My Karaoke」設計書 v1.3 を初期リリース要件として採用。
- アップロードされた Project Forge ZIP はアプリ本体を含まず、Project Forge v0.4 の開発管理・QAプロトコルのみを含んでいたため、アプリは本フォルダ内に新規作成。
- チャットで明示された「PWAの実装」の指示に基づき、製品実装を開始。元ZIPの H-001（Project Forgeのブートストラップ検証）は製品実装とは別の管理タスクであり、PASSと偽っていない。

## AI-DECIDED 実装判断

1. **Vanilla JavaScript（ES Modules）**：仕様でフレームワーク必須ではなく、外部依存を避け、オフライン配信を簡単にするため。
2. **IndexedDB schemaVersion 1**：songs / scoreRecords / settings を分離し、曲削除と関連履歴削除は同一トランザクションで処理。
3. **scoreMilli整数保存**：点数は1000倍整数として保持し、平均表示時だけ整数単位で四捨五入。
4. **全データをローカル処理**：外部API・アカウント・アプリサーバーを使わず、Service Workerで静的アプリファイルをキャッシュ。
5. **追加インポートは非破壊優先**：同一ID同一内容はスキップ、同一ID異内容は競合扱い、既存レコードは上書きしない。設定キーも既存値を優先。
6. **表示倍率抑止**：viewport指定と `touch-action: pan-x pan-y` を使用。OS・ブラウザのアクセシビリティ拡大機能は対象外。
7. **画面状態**：曲詳細・新規登録から一覧に戻る際、検索・絞り込み・並び替えと一覧スクロール位置を可能な範囲で維持。
